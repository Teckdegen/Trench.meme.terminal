# trench.meme — Launch & Hosting Guide

Everything you need to take this from local clone → live in production. Read once top-to-bottom, then follow the checklist at the bottom.

---

## 1. What this is

**trench.meme** is an onchain trading terminal for **Monad mainnet** (chain id `143`). It bundles:

- **Trading**: manual swaps, limit orders, copy trades, auto-snipers — all signed server-side via the user's Privy embedded wallet (zero popups after first login)
- **Onchain intel**: 24/7 trade indexer, PnL snapshots, smart-money labels, custom bubble maps, user-configurable alerts
- **Social**: posts (X-style 200-char limit), follows, replies, likes, reposts, mentions, cashtags, verified badges, a `trenchmem` official announcer
- **Cabals**: end-to-end encrypted group chats (Discord-style UI) with nested voice rooms (Agora), pinned-token watchlists that auto-post trade alerts in chat
- **DMs**: pure peer-to-peer Gun.js, wallet = inbox key (same chats on every device)
- **Floating chat bubbles**: DMs / cabals / notifications accessible from every page
- **Rewards**: cashback + referral points, MON redemption with tier multipliers
- **Reports + rate limits + account deletion** built in

The frontend ships to **Vercel**. All background workers ship to **Railway** as one container.

## 3. Required external services

You need accounts on all of these before you can launch.

| Service | What it does | Cost at 2k DAU |
|---|---|---|
| **Vercel** | Hosts the frontend | Free (Hobby) or $20/mo (Pro) |
| **Railway** | Hosts the bot workers + Gun relay | ~$10-30/mo (compute + volume) |
| **Supabase** | Postgres DB + auth + Realtime | $25/mo (Pro — required for Realtime quota) |
| **Privy** | Embedded wallets + delegated signing | $499/mo (Scale tier at ~6-10k MAU) |
| **Agora.io** | Voice rooms inside cabals | Free tier ~10k mins/mo, then ~$0.99/1k mins |
| **Nad.fun** | Curve token API + WebSocket for sniper | Free with API key (10 req/min anon, 100 req/min keyed) |
| **Dirol** | DEX swap routing for graduated tokens | Free public API |
| **Plausible** *(optional)* | Privacy-friendly analytics | $9/mo |
| **WalletConnect** *(if you want external wallets)* | Project ID for WC v2 | Free |
| **Monad RPC** | Read/write chain access | Use a paid provider (Alchemy/QuickNode/Ankr) for production reliability |

**Total realistic monthly bill at 2k DAU: $550–700/month** (dominated by Privy + Supabase).

## 5. Setting up each service

### 5.1 Supabase

1. Create a new project on [supabase.com](https://supabase.com). Pick the region closest to where most of your users live.
2. Upgrade to **Pro** ($25/mo) — the free tier's Realtime connection cap (~200 concurrent) will choke at your first viral moment.
3. Open the SQL editor → paste the entire contents of `supabase/schema.sql` → run.
4. Grab from **Settings → API**:
   - `Project URL` → this becomes `VITE_SUPABASE_URL`
   - `anon public` key → becomes `VITE_SUPABASE_ANON_KEY`
   - `service_role` secret key → becomes `SUPABASE_SERVICE_ROLE_KEY` (**workers only — never frontend**)

### 5.2 Privy

1. Sign up at [privy.io](https://privy.io), create a new app for trench.meme.
2. In **App settings → Login methods**: enable email, Google, Twitter, Apple, Discord, Telegram, Farcaster, and external wallets.
3. In **App settings → Embedded wallets**: enable, set "Create on login: users without wallets", enable **"Sign transactions without prompting"** (called "delegated actions" or "session signers" depending on Privy version).
4. In **App settings → Networks**: add **Monad** (chain id `143`), RPC URL of your choice, currency `MON`.
5. Grab:
   - `App ID` → `PRIVY_APP_ID` (both frontend and bot env)
   - `App Secret` → `PRIVY_APP_SECRET` (**bot only**)
   - If your app requires authorization keys: generate one → `PRIVY_AUTHORIZATION_KEY` (bot only)

### 5.3 Nad.fun API key

The Nad.fun API needs a per-account key for production rate limits (100 req/min vs the anonymous 10 req/min).

Use the included script:

```bash
node scripts/register-nadfun-key.js \
  --network mainnet \
  --private-key 0x...your-key... \
  --name "trench.meme indexer"
```

The script handles the full nonce → sign → session → key flow described in the Nad.fun API doc and prints the issued `nadfun_...` key. Store it as `NADFUN_API_KEY` in the bot env.

See [§9](#9-nadfun-api-key-script) below for full script details.

### 5.4 Monad RPC

For local/dev, the public `https://rpc.monad.xyz` works fine. For production:

- HTTPS endpoint → `MONAD_RPC_URL`
- WebSocket endpoint → `MONAD_WS_URL` (this is what the indexer + sniper hook into)

Get paid endpoints from **Alchemy** (most reliable), **QuickNode**, or **Ankr**. Public endpoints throttle aggressively and will drop events under load.

### 5.5 Agora.io (voice rooms)

1. Sign up at [agora.io](https://www.agora.io/).
2. Create a new project, copy:
   - `App ID` → `VITE_AGORA_APP_ID` (frontend)
   - `App Certificate` → `AGORA_APP_CERTIFICATE` (frontend server-fn env, for token minting)

If you skip Agora, the voice channels just show "Voice not configured" — everything else still works.

### 5.6 WalletConnect (only if you want external wallets in addition to Privy's embedded)

1. Create a project at [cloud.walletconnect.com](https://cloud.walletconnect.com/).
2. Copy the project id → `WALLET_CONNECT_PROJECT_ID` (frontend server-fn env).

### 5.7 Fee wallet

This is the wallet that receives the silent platform fee on every executor swap (0.85% market / 2.5% limit / 3.5% copy / 2.5% sniper).

1. Generate a fresh wallet: `node -e "console.log(require('viem/accounts').generatePrivateKey())"`
2. Fund it with ~0.5 MON for gas (the redemption worker uses this wallet to send MON cashback).
3. Set:
   - `FEE_WALLET_ADDRESS` (bot env)
   - `FEE_WALLET_PRIVATE_KEY` (bot env — **keep this safe**)

## 6. Local development

### 6.1 First-time setup

```bash
# Clone + install
git clone <your-repo> trench.meme
cd trench.meme

# Run the setup script — generates random keys + writes env templates
./scripts/setup.sh

# Edit the generated .env files and fill in real values from §5
$EDITOR .env.local
$EDITOR bot/.env

# Frontend deps
npm install

# Bot deps
cd bot && npm install && cd ..

# Run the database migrations (once)
# Paste supabase/schema.sql into your Supabase SQL editor and run it
```

### 6.2 Running it

```bash
# Terminal 1: frontend
npm run dev
# → http://localhost:3000

# Terminal 2: all bot workers via PM2
cd bot
npm run all
# pm2 logs              ← watch all workers
# pm2 restart all       ← restart on env changes
```

Or run individual workers:

```bash
cd bot
npm run indexer
npm run executor
npm run sniper-worker
npm run gun-relayer
# ...etc, see bot/package.json
```

## 7. Production deployment

### 7.1 Frontend → Vercel

1. Push the repo to GitHub.
2. **Import the repo** on Vercel. It auto-detects TanStack Start.
3. **Environment variables** (Settings → Environment Variables):

| Var | Value |
|---|---|
| `VITE_SUPABASE_URL` | from §5.1 |
| `VITE_SUPABASE_ANON_KEY` | from §5.1 |
| `SUPABASE_SERVICE_ROLE_KEY` | from §5.1 (server-fns only) |
| `PRIVY_APP_ID` | from §5.2 |
| `VITE_MONAD_RPC_URL` | your paid RPC HTTPS |
| `VITE_GUN_PEERS` | `https://<your-railway-domain>/gun` (set AFTER bot is deployed) |
| `VITE_AGORA_APP_ID` | from §5.5 (optional) |
| `AGORA_APP_CERTIFICATE` | from §5.5 (optional) |
| `WALLET_CONNECT_PROJECT_ID` | from §5.6 (optional) |
| `VITE_PLAUSIBLE_DOMAIN` | `trench.meme` (optional, enables analytics) |

4. **Deploy**. First build takes ~3 minutes.
5. Add your custom domain (Settings → Domains).
6. `vercel.json` is already in the repo — it ships CSP headers, asset caching, and the `/@:handle → /profile/:handle` rewrite automatically.

### 7.2 Bot → Railway

1. **Create a new Railway project**, point at the same GitHub repo.
2. **Settings → Service → Root directory**: set to `bot`.
3. **Builder**: auto-detects via `railway.json` → uses the `Dockerfile`. No config needed.
4. **Environment variables** — paste the entire `bot/.env.example` and fill in real values. The full required list:

```
# Supabase
VITE_SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=

# Monad
MONAD_RPC_URL=https://...                 # paid RPC
MONAD_WS_URL=wss://...                    # paid WS

# Nad.fun
NADFUN_API_BASE=https://api.nad.fun
NADFUN_API_KEY=nadfun_xxxxx...

# Privy server SDK
PRIVY_APP_ID=
PRIVY_APP_SECRET=
PRIVY_AUTHORIZATION_KEY=                  # optional, only if your app requires it

# Sniper observer (read-only burner key, no funds)
SNIPER_OBSERVER_KEY=0x...

# Gun relay
GUN_HOST=0.0.0.0
GUN_DATA_DIR=/data                        # mount a Railway Volume here
GUN_ALLOW_ORIGIN=https://trench.meme      # tighten in prod

# Platform fees (silent)
FEE_WALLET_ADDRESS=0x...
FEE_WALLET_PRIVATE_KEY=0x...
WMON_ADDRESS=0x3bd359C1119dA7Da1D913D1C4D2B7c461115433A
FEE_BPS_MARKET=85
FEE_BPS_LIMIT=250
FEE_BPS_COPY=350
FEE_BPS_SNIPER=250

# Gun janitor retention
GUN_MAX_MESSAGE_AGE_DAYS=90
```

5. **Volume**: create a Railway Volume, mount at `/data` (so the Gun relay's radisk store survives restarts).
6. **Networking**: click **Generate Domain** on the service — you'll get something like `your-bot.up.railway.app`. Take that domain and set `VITE_GUN_PEERS=https://your-bot.up.railway.app/gun` in your Vercel env vars (then redeploy frontend).
7. **Region**: pick the region closest to your Supabase region (lowest DB query latency).
8. **Healthcheck**: `railway.json` already points at `/health` on the gun-relayer port — Railway will auto-restart if the relay dies.

### 7.3 Optional: split bot into multiple services

If you want **gun-relayer isolated** so chat traffic doesn't share CPU with the executor:

1. Create a second Railway service pointed at the same repo, root dir `bot`.
2. Change its **Start command** to `npm run gun-relayer`.
3. Drop the `gun-relayer` entry from `bot/ecosystem.config.cjs` on the first service.

Same pattern works to scale the executor horizontally — run N copies, partition queue rows by `id % N`.

## 8. Post-deploy smoke test

Run this every time you push a release:

```
1. Open https://trench.meme in incognito
2. Sign in via Privy modal (email or Google)
3. Browser should land back at the dashboard with your wallet address in the top-right pill
4. Click "Add Funds" → Deposit → confirm address + Monad logo show
5. Send a tiny amount of MON to that address from another wallet
6. Within ~3s the balance should update
7. Open /cabals → create a cabal → send a message → confirm the green shield (signed) appears
8. Open a token page → click Buy → enter 0.01 MON → confirm
9. Within ~2.5s a "trade filled" toast should appear, with a tx hash linking to MonadScan
10. Check Railway logs — executor should log "executor: market BUY → 0x..."
11. Try the sniper page → arm a config → confirm it saves and shows in your list
12. Open /alerts → confirm any notifications fire correctly via Realtime
13. Test withdrawal: /wallet → Withdraw → 0.001 MON to a different address
```

If steps 8-10 fail, the issue is almost always a missing Privy config (delegated actions disabled, Monad chain not added, or auth key mismatch). Check Railway logs for the exact error.

## 10. The complete launch checklist

Go through this top-to-bottom before announcing. Estimate 2-3 days from "have all accounts" → "live on a custom domain".

### Pre-flight
- [ ] All external accounts created (§3)
- [ ] Supabase Pro tier active

- [ ] Verified RLS is enabled on every table (`select tablename from pg_tables where schemaname='public' and rowsecurity=false;` returns nothing public)

### Frontend
- [ ] All env vars set on Vercel (§7.1)
- [ ] `npm run build` succeeds locally
- [ ] Custom domain pointed at Vercel
- [ ] `vercel.json` is at repo root (CSP + rewrites)

### Bot
- [ ] All env vars set on Railway (§7.2)
- [ ] Railway Volume mounted at `/data`
- [ ] Railway domain generated, set as `VITE_GUN_PEERS` on Vercel
- [ ] `GUN_ALLOW_ORIGIN` tightened to your real domain
- [ ] All 12 workers green in Railway logs

### Test trades
- [ ] Sign-in works (Privy modal → wallet address appears)
- [ ] Deposit address shows MON logo + correct copy
- [ ] Test wallet funded
- [ ] Manual buy succeeds, tx hash appears on MonadScan
- [ ] Manual sell succeeds
- [ ] Sniper armed + fired on a test Nad.fun launch
- [ ] Copy trade fired when target wallet traded
- [ ] Limit order placed + filled when price crossed

### Polish
- [ ] Self-hosted MON logo at `/public/mon-logo.png` (don't depend on Twitter URL)
- [ ] Plausible analytics live (or another provider configured)
- [ ] Sentry installed (`window.Sentry` is what `AppErrorBoundary` checks for)

### Soft launch
- [ ] Share with 5-10 friends. Watch Railway logs. Fix everything that breaks.
- [ ] After 24h of clean operation → public announcement.

## 11. Operational gotchas

- **Privy SDK drift**: if a trade errors with `Privy sendTransaction returned no hash` or similar, see the inline notes in `bot/scripts/lib/privy-signer.ts` — fixes are a 1-line edit.
- **Realtime quota**: each open tab subscribes to ~5 channels (follows, notifications, trades, cabal_members, posts). At 200 concurrent connections you start dropping users. Pro tier raises this to ~500. For 10k+ DAU, consider scoping subscriptions per route.
- **Sniper queue spam**: if your sniper hits more configs than the executor's fast-tick can drain, queue backs up. Either lower `executor` tick interval below 500ms, OR run multiple executor instances and partition by `owner_address`.
- **Gun storage growth**: `gun-janitor` worker prunes old messages, typing indicators, and reactions every 10 min. If your Railway Volume fills up, raise `GUN_MAX_MESSAGE_AGE_DAYS` down (default 90).
- **Fee wallet drain**: every executor trade tries to send the platform fee to `FEE_WALLET_ADDRESS`. The wallet itself doesn't need MON — but the **redemption worker** uses `FEE_WALLET_PRIVATE_KEY` to send MON cashback to users. Keep it funded.

## 12. Killing it (rollback / shutdown)

- **Stop the bot**: `pm2 stop all` on Railway, or pause the service in dashboard.
- **Drain the queue**: `update execution_queue set status='cancelled' where status='pending';` — refund handling is on you.
- **Disable trading without shutdown**: revoke Privy delegated actions in the Privy dashboard. Existing logged-in users will be prompted to re-grant. Read-only social features still work.
- **Delete a user**: they hit Settings → Delete Account, which calls the `delete_my_account()` RPC. Cascades through every FK.
